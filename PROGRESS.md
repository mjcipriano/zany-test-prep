# PROGRESS — Zany Test Prep (offline SAT + ACT app)

> Living handoff doc. Any agent can read this and continue. Update it as you go.
> Original spec lives in [PROMPT.md](PROMPT.md). Repo: https://github.com/mjcipriano/zany-test-prep

## How to get a working environment

```bash
bash scripts/setup_env.sh      # one-time: mamba env + Flutter SDK + Android SDK into .tooling/
source scripts/activate.sh     # every shell: puts flutter/dart/java/sdkmanager on PATH
flutter doctor                 # Flutter + Android toolchain should be green
```

Everything project-specific is isolated:
- `environment.yml` → mamba env `zany-test-prep` (JDK 17 + python content tooling; Pillow
  is optional, used by `tools/sync_avatars.py` to downscale sprites).
- `.tooling/` (git-ignored) → Flutter 3.35.5 SDK + Android SDK 35, installed by `scripts/setup_env.sh`.

## Branch / merge workflow

Work on short-lived feature branches off `master`, then merge into `master` yourself
(no PR gate required for this internal project). Keep `master` green. Push to save.
Tag `vX.Y.Z` to cut a release (CI builds + attaches the APK, see docs/release.md).

## Latest state (v2.0.0)

- **Two exams.** SAT and ACT. Onboarding offers every exam listed in
  `assets/content/exams.json`; Settings → Exam switches (XP/streak/rewards carry
  across; each exam keeps its own lesson progress; mastery is per exam via
  `masteryKey`). Nothing in `lib/features/` hard-codes an exam: domains, the timed-test
  layout and the score scale come from the bundle (`Exam.timedTest`, `Exam.scoring`,
  `ExamScoring` — SAT 200–800/1600, ACT 1–36 + composite of English/Math/Reading).
- **Content:** SAT <<SAT_LESSONS>> lessons / <<SAT_QUESTIONS>> questions; ACT
  <<ACT_LESSONS>> lessons / <<ACT_QUESTIONS>> questions (English, Math with 5 choices,
  Reading, Science). Generated by `tools/generate_content.py` walking per-exam plans
  (`tools/content_gen/exam_plans.py`) over **question families** (`registry.py`):
  every skill has several distinct question forms per difficulty, round-robined within
  each lesson, and the validator fails any generated lesson with < 3 families or one
  family > 50% (`low_variety_lessons`). ACT English fill-ins are rewritten into the
  bracketed-portion / NO CHANGE format (`exam_plans.act_no_change`).
- **Generators:** math (`math_gen.py`, `math_extra.py`, ACT-only `math_act.py`),
  writing (`rw_gen.py`, `rw_extra.py`, ACT usage `rw_act.py`), reading passages
  (`passages*.py`, shared), science (`science_gen.py`: 22 computed experiment scenarios
  + 13 authored Scientist 1/2 pairs), teaching cards (`teaching*.py`).
- **Avatar & pets:** pack `mjcipriano/zany-test-prep-avatars` **v3.0.0** vendored by
  `tools/sync_avatars.py --full` (sprites downscaled to 384 px; `--local <checkout>`
  copies from disk). Pets level up while equipped (`PetEngine`) and evolve through
  Base → Shiny → Radiant stages (`RewardsService.evolvePet`); the store sells base
  stages only. `AvatarPreview` fits sprites to their aspect ratio, rests headwear on a
  brow line (`kHeadwearBrimLine`, except `floating` items), adds shadows/glow and an
  idle float. Layout is guarded by `test/render/catalog_geometry_test.dart` (whole
  catalog) and the pixel tests in `test/render/overlap_test.dart`.
- **Quality:** `flutter analyze` clean; `dart format` clean; Flutter suite ~<<DART_TESTS>>
  tests; Python tooling suite (`python -m unittest discover -s tools/tests -t .`) covers
  the registry, plans, orchestrator, validator, bundler and every generator family. CI
  runs all of it plus the validator for every exam and the bundle-freshness check.
- **Bug fixes in 2.0.0** (from a full review of lib/): review sessions no longer
  dead-end when every answer is right; double-tap on Finish/See results/chest no longer
  applies twice; a timed-test section cannot be scored twice; review queue and Home badge
  are scoped to the active exam; corrupt profile + onboarded flag re-onboards instead of
  spinning; backup import for an unshipped exam stays consistent; day math is DST-safe;
  empty avatar catalog no longer crashes.

## Key commands

```bash
python tools/generate_content.py          # regenerate every exam (or --exam act)
python -m unittest discover -s tools/tests -t .   # tooling + generator tests
python tools/validate_content.py          # validate every exam (CI)
python tools/build_bundle.py              # build assets/content/*.bundle.json + exams.json
python tools/sync_avatars.py --full       # vendor the avatar pack (--tag vX.Y.Z)
flutter test                              # unit + widget + persistence + render tests
flutter test integration_test            # on-device end-to-end test
flutter build apk --release               # release APK -> build/app/outputs/flutter-apk/
```

## Architecture (quick map)

- `lib/app/` — `AppController` (Riverpod AsyncNotifier; bootstrap/lessons/review/profile/
  exam switch/rewards/pets/backup), `router.dart` (GoRouter), `app.dart`.
- `lib/domain/models/` — exam (timed test + scoring), skill/lesson/question/content_bundle,
  profile, progress (per-exam mastery keys, pet XP), avatar_catalog (evolution, variants),
  backup, reward.
- `lib/domain/services/` — answer_checker, leveling, streak, mastery, unlock, review,
  scoring, badges, game_service (applies a session: XP, streak, mastery, review, pets),
  rewards_service (chests, store, equip, pets/evolution), reward_engine, pet_engine.
- `lib/data/` — `KeyValueStore` (shared_preferences + memory), content/progress/avatar repos.
- `lib/features/` — onboarding (exam picker), home (one path per domain), lessons,
  practice (balanced sampling), review, diagnostic, test (timed test per exam),
  progress (dashboard/skills), rewards (hub, chest, store, customizer + companions),
  settings (exam switch, backup, about).
- Canonical content in `content/exams/{sat,act}/`; runtime bundles in `assets/content/`.
- Docs: README + docs/ (architecture, content, content-authoring, gamification,
  persistence, release, roadmap, content-review). AI prompt docs in `content/prompts/`
  (SAT + ACT variants).

## Notes / decisions

- Content is generated by deterministic Python generators (fixed seed per exam) →
  reproducible and auditable; math/science answers are computed, writing is rule-based.
- Skill ids shared between exams reuse one generator; mastery is still scoped per exam
  (`sat` keeps bare keys for backward compatibility, other exams use `<exam>:<skill>`).
- Persistence is JSON in `shared_preferences` behind `KeyValueStore`; all `fromJson` are
  defensive (`safe_json.dart`) so updates never crash on old data.
- Widget tests inject the real bundles synchronously (`test/helpers/pump_app.dart`) and an
  in-memory store, so the suite is deterministic and headless.
